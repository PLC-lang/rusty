# E156 - Operator not defined for these date or time operands

Arithmetic on date and time types is only defined for the combinations of IEC 61131-3:

| Left | Operator | Right | Result |
|---|---|---|---|
| `TIME` | `+`, `-` | `TIME` | `TIME` |
| `TIME_OF_DAY` | `+`, `-` | `TIME` | `TIME_OF_DAY` |
| `DATE_AND_TIME` | `+`, `-` | `TIME` | `DATE_AND_TIME` |
| `TIME_OF_DAY` | `-` | `TIME_OF_DAY` | `TIME` |
| `DATE` | `-` | `DATE` | `TIME` |
| `DATE_AND_TIME` | `-` | `DATE_AND_TIME` | `TIME` |
| `TIME` | `*`, `/` | any number | `TIME` |
| any number | `*` | `TIME` | `TIME` |

The long types `LTIME`, `LTIME_OF_DAY`, `LDATE` and `LDATE_AND_TIME` follow the same table. Any
other combination still compiles as a plain integer operation on the stored nanoseconds, but the
next version rejects it, so it is reported as a warning. The same warning is given when a short
type meets a long one, for example `TIME + LTIME`: here the two are the same type, but the next
version makes the short types 32 bit wide and rejects the combination.

Code example:

```iecst
PROGRAM mainProg
VAR
    start, stop : DATE_AND_TIME;
    total : DATE_AND_TIME;
END_VAR
    total := start + stop;
END_PROGRAM
```

Two points in time do not add up. Their difference is a duration:

```iecst
PROGRAM mainProg
VAR
    start, stop : DATE_AND_TIME;
    elapsed : TIME;
END_VAR
    elapsed := stop - start;
END_PROGRAM
```
