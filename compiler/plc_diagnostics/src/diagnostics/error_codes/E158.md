# CFC execution order 0

An element in a CFC network has the execution order 0. The IDE numbers the
execution orders of a network from 1, so it never exports an order of 0. An
element with order 0 means the project file was changed outside of the IDE or
is corrupted.

```
foo --> bar (0)    rejected
foo --> baz (1)
```

The debugger shows the elements of a diagram by their execution order: element
1 is line 1 of the diagram, element 2 is line 2. Line 0 means "no source line",
so a debugger could never stop on an element with order 0. Open the network in
the IDE and save it again, so that every element gets a valid order.

## Technical details

In the exported CFC file, the execution order is the `priorityInNetwork`
attribute of the element's `EvaluationPriority`. The element is rejected when
the attribute is 0:

```xml
<EvaluationPriority priorityInNetwork="0"/>    <!-- rejected -->
<EvaluationPriority priorityInNetwork="1"/>    <!-- the first valid order -->
```
