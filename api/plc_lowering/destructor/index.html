Module destructor 

Source
Expand description

The destructor lowering module generates destructor functions (__dtor) for the types and POUs of a compilation unit that need cleanup. It is the mirror of the initializer lowering.

§Which types need a destructor

  • A function block, class, or program that declares an FB_EXIT method.
  • A type that owns an instance of such a type: as a member, a struct field, an array element, or through its base type.

All other types get no destructor and no destructor calls. Pointers, references, and VAR_IN_OUT variables do not own the instance they refer to.

§Destructor generation

  • The destructor <TypeName>__dtor calls the FB_EXIT method of the type, then the destructors of the members in reverse declaration order, then the destructor of the base type.
  • The destructor of an array type calls the destructor of each element in ascending order.

§Global cleanup

  • Program instances and global variables are cleaned up in a per-module function called __unit_<name>__dtor, registered via LLVM’s .fini_array for automatic execution when the module is unloaded. Its order is the reverse of the unit constructor.

§Stateless POUs

  • Local variables of functions and methods, VAR_TEMP variables of every POU, and the return value of a function are constructed on each call. Their destructors are called on each path that leaves the body: before every RETURN and at the end.

§Linkage behavior

  • Destructors follow the same linkage rules as constructors: types from included (-i) or external units get a declaration only, unless external constructors are generated.
